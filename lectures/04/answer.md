## 宿題

- 取り組んだレベル：発展
- やったこと：SWE-bench Verifiedについて、評価用の問題や作成に関わった人の人数・立場、検証手順、採点方法などを調べた。 [Link](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified)
- 結果：
  - SWE-bench Verifiedは、実在するオープンソースPythonプロジェクトのGitHub Issueに記載された課題を、コードの変更によって解決できるかを測るベンチマーク。
  - 問題例：

    | Issue | 概要 |
    |---|---|
    | [Modeling's separability_matrix does not compute separability correctly for nested CompoundModels](https://github.com/astropy/astropy/issues/12906) | 独立な線形モデルを単純につないだ場合は正しい対角成分になるのに、それらを入れ子にした `CompoundModel` として渡すと、本来独立な入力・出力まで依存しているように表示される。モデルを入れ子にしても数学的な依存関係が変わらないように直すことが求められる。 |
    | [`kernS`: 'kern' referenced before assignment](https://github.com/sympy/sympy/issues/19608) | `kernS("(2*x)/(x-1)")` を実行すると、ローカル変数 kern を代入前に参照して `UnboundLocalError` が発生する。本来は例外を出さずに数式 `2*x/(x-1)` として処理できるようにする。 |
    | [Use Python type hints for UML generation](https://github.com/pylint-dev/pylint/issues/1548) | `pyreverse` のUML図生成がPythonの型注釈を十分に読まない。型ヒントを解析して、属性などの型を図に表せるようにする課題。 |
  - 作成者：元のSWE-benchは7人の論文著者による研究。Verified版はその研究者らとOpenAIが共同で作成した。2024年の公式記事には16人の著者が記載され、実際の人手による品質確認にはPython経験を持つソフトウェア開発者93人が参加した。
  - 検証手順：元となるSWE-benchの2,294件から無作為に1,699件を抽出し、各問題を3人が独立して検証した。問題文の曖昧さやテストの不備などを調べ、約68.3%を除外した後、難易度も考慮して500件を選定した。
  - 採点方法：自動テストによる実行評価
    1. エージェントにIssue本文と修正前のコードベースを与える。
    2. エージェントがファイルを変更し、パッチを提出する。
    3. パッチが適用できるか確かめ、Docker等の評価環境で2種類のテストを実行する。
       - FAIL_TO_PASS：修正前は失敗し、修正後には成功するテスト。今回の不具合を直せたかを見る。
       - PASS_TO_PASS：修正前も修正後も成功するテスト。他の既存機能を壊していないかを見る。
    4. 両方のテストをすべて通過した問題だけを「解決（resolved）」と判定し、`解決件数 ÷ 対象件数 × 100%` を解決率（resolve rate）として集計する。
  - その他：OpenAI o3が64回の試行で安定して解けなかった138件を再監査し、少なくとも6人の経験豊富な開発者が各問を個別に確認したところ、その59.4%にテスト設計または問題記述の重大な欠陥が見つかったと発表した。
- 気づき・疑問：
  - ベンチマークの作成には16人の著者に加え、93人の開発者が検証に関わっており、多大な労力とコストが投じられていることがわかる。
  - 一方、採点には自動テストを用いることで、時間とコストを大幅に削減している。
  - 個々の問題の難易度が高いだけでなく、コードベース全体を理解したうえでIssueに対応する必要があり、課題全体の難易度も高い。
  - これほど労力をかけて作成されたベンチマークでも、再監査によって重大な欠陥が見つかることから、評価指標の設計がいかに難しいかがわかる。
  - 第4回の評価セットは用語の説明や指示遵守などを確認するものであるのに対し、SWE-bench VerifiedはIssueに対応するコードを修正できるかを評価している。評価対象の問題数（10件／500件）や採点方法（人とLLMによる回答評価／自動テスト）も異なる。
